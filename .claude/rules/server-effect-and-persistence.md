# Rule: server Effect conventions, buses, persistence & auth

**Scope:** `packages/server/` — read before writing handlers, wiring layers, publishing events, or touching SQL/auth.
**Backing ADRs:** 0004 (errors as tagged errors), 0006 (typed bus), 0007 (unit of work + event buses), 0012 (observability/spans), 0016–0017 (auth via Zitadel BFF), 0020 (per-module DB schemas).

- **Errors as `Schema.TaggedErrorClass`** (ADR-0004; `Schema.TaggedError` in effect v3). Domain errors live in `domain/`, contract errors live in the contracts package, and the HTTP endpoint maps domain → contract via `Effect.catchTag`.
- **Typed bus** (ADR-0006). `bus.execute(SomeCommand, {...})` returns the exact `Effect<A, E, never>` the message's own definition declares — the definition is the single source of truth, so there is no registry to keep in sync. No casts, no `Result` unwrapping. Messages are declared with `Command.make`/`Query.make` from `@effect-server-utils/cqrs`; each definition publishes a `<Name>Payload` type its handler names. A definition's exported identifier **is** its tag (`CreateUserCommand`, `FindUsersQuery`) and its handler is `<name>Handler` — so `bus.execute(CreateUserCommand, …)` reads as a command at the call site (ADR-0024). Dispatchers are per-module surfaces (`XCommands`/`XQueries`) composed in dependency order at the composition root, so a handler that reaches another module resolves against that module's surface instead of the whole bus.

  Three things ride on the bus that are easy to miss. **Middleware**: `Command.dispatcher(group, { middleware })` wraps each tag, outermost-first; a middleware may **not** change the success or error channels (a _channel_ check is therefore a test, not dispatch-time validation — though the transport does construct each payload through its own schema, so a value violating the schema it was declared with fails that dispatch). Tracing is itself the default middleware — the transport opens no spans. `Middleware.metrics()` and `Middleware.deadline(duration)` are opt-in; `deadline` centralises a time limit and raises expiry as a defect (`DeadlineExceeded`). Interruption reaches a handler from either direction — a caller's own `timeout`/`race`, or an interrupt applied from outside the dispatching fiber — so a client hanging up aborts the command and rolls its transaction back; `deadline` is a convenience, not the only way to stop one. A handler's defect stays with its own caller (the transport is built with `disableFatalDefects`, without which one defect fails every dispatch in flight beside it). **Boot completeness**: the composition root passes `declaredIn: [...groups]` and the bus refuses to build if the table does not cover them, raising `UnroutableTags`; `DuplicateDispatchTag` and `MissingHandler` are the other two tagged wiring defects. `declaredIn` means "the groups this bus routes", not every group the app declares — a `*.policy-query.ts` is deliberately absent, since it is reached only through a consumer's own ACL adapter. **Serializability**: `checkSerializable` / `checkEventsSerializable` from **`@effect-server-utils/cqrs/testing`** (a separate entry point, so `fast-check` stays out of the production import graph) assert a message's channels round-trip through JSON; each module owns a test. It is quiet for ordinary schemas and fires on `Schema.Unknown` and `Schema.instanceOf`.

- **Unit-of-work boundary + one event bus** (ADR-0007). The boundary lives in **`@effect-server-utils/unit-of-work`** and the bus in `@effect-server-utils/cqrs`; the server supplies only `TransactionDriverLive` (the SQL binding for "open a scope / open a nested scope / is one open", now three lines over `SqlClient.withTransaction`, which is itself depth-aware). Command handlers declare the transaction once at the boundary with `.pipe(withUnitOfWork)` (not an inner `uow.run` block); it demotes `TransactionFailed` to a defect and surfaces `PersistenceUnavailable`. The port leaves `R` untouched — do not reintroduce an `Exclude` for the transaction context; the client resolves the ambient connection internally, so it never enters a caller's requirements. `dispatch` hands its events to the ambient `DeferralSink` **before** any immediate handler runs; `makeUnitOfWork` installs that sink, and it dies with `EventDispatchedOutsideUnitOfWork` when no scope is open — so a forgotten `withUnitOfWork` still fails fast, and it fails while the dispatch is still whole. The bus itself names no transaction: with no sink in context it drains its own after-commit handlers at the end of each dispatch. `UnitOfWorkScope` is no longer public — reach for `PassThroughUnitOfWork` from `@effect-server-utils/unit-of-work/testing` instead of hand-rolling a pass-through. Post-commit handler failures and dead sagas are logged **and** reported to `UnhandledFailures` (ambient, optional). Long-running reactions that need several events, a timeout, or compensation are `Saga.make` + `Saga.runner`, in a module's `sagas/` folder — restart-lossy by design; reach for an `interface/events/` adapter first. `UnitOfWork.run` is the low-level escape hatch (integration tests, sub-blocks that keep external IO outside the tx). Nested runs open a real **savepoint**: a caught nested failure rolls back only the savepoint while the outer commits. There is **one** bus, and the **subscription** picks the consistency model — never the publisher, which under ADR-0022 usually may not know its consumers: `subscribe` (immediate; runs in the publisher's fiber/transaction, a failure rolls the publisher back) vs `subscribeAfterCommit` (eventual; deferred to the sink, the outermost `run` drains after commit via `EventBus.drain`, each handler in its own transaction with failures logged/isolated) vs `stream` (post-commit, never awaited — the saga substrate). One event can carry both kinds of consumer. Default new cross-aggregate reactions to `subscribeAfterCommit`. `dispatch` outside a unit of work is a defect (fail-fast on a forgotten `withUnitOfWork`); dispatching _after_ the `withUnitOfWork` block is not a post-commit idiom — it is that defect. The package names it `EventBus`; the server re-imbues DDD vocabulary in `platform/ddd/event-bus.ts`, which sits outside the `contracts/` tier `domain/` may reach — that placement is what keeps the bus out of the domain. In-memory drain for now (lossy on commit-then-crash); transactional outbox is the deferred durability follow-up.
- **Ports vs Lives** (ADR-0007). The DDD shared kernel moved into `@effect-server-utils/cqrs` + `@effect-server-utils/unit-of-work`; `platform/ddd/` holds `contracts/` (the specification kit plus the two domain-safe re-exports) and `event-bus.ts` (the `DomainEventBus` alias over the CQRS package's `EventBus`). **`domain/` never names either library.** Their domain-safe modules are re-exported under DDD vocabulary from `platform/ddd/contracts/` — `domain-event.ts` (`Event.make`, `DomainEvent`, `SpanAttributesExtractor`, from cqrs) and `persistence-unavailable.ts` (from unit-of-work) — and `domain-isolation` allowlists that folder, not package paths, so the rule does not depend on the library's internal file layout. The bus alias is `platform/ddd/event-bus.ts`, one level _outside_ `contracts/`, which is what keeps a bus out of a domain port's requirement channel. Everything outside `domain/` uses the barrel. The only Live left in `platform/` for this surface is `transaction-driver-live.ts` (the SQL binding); the bus and unit-of-work layers are built in `cqrs-runtime.ts`. Lives are wired at the composition roots (`server.ts`, `cqrs-runtime.ts`, `test-utils/test-server.ts`) and in integration tests that intentionally stage a sub-graph, enforced by `lives-only-from-composition-roots`; `domain-isolation` admits `platform/ddd/contracts/`, which is why domain imports the event vocabulary from there rather than from the package.
- **The command/query buses come from `@effect-server-utils/cqrs`, not `platform/ddd/`** (ADR-0006). Import `CommandBus` / `QueryBus` (the Tags) from `@effect-server-utils/cqrs`. A module publishes its own slice with `Command.dispatcher(group, { spanAttributes })` in `<feature>.command-handlers.ts` and exports it as a Tag from its barrel. `makeCommandBus` / `makeQueryBus` / `mergeDispatchTables` fold those into one routing table and are restricted to the composition roots by the `bus-factories-at-composition-roots` lint rule — a path rule can't reach them through the package barrel. There are now **three** composition roots: `server.ts`, `test-utils/test-server.ts`, and `cqrs-runtime.ts` (the slice they share verbatim — the buses, the event buses, `UnitOfWorkLive`, `UnhandledFailuresLive`). Only module _ordering_ stays duplicated in the two outer roots, because the test runtime takes billing's fake gateway.
- **Spans: boundary + use-case** (ADR-0012). Spans live at the command/query/event bus and at HTTP endpoints, plus a use-case span per handler declared with `Effect.fn("<handlerName>")` — instrument at use-case granularity, no finer. HTTP/CLI **endpoint adapters** also declare their boundary span via `Effect.fn("<GroupLive.op>")` (not an explicit `Effect.withSpan`) — the effect-v4 idiom, and what `@effect/language-service`'s `effectFnOpportunity` steers toward. Span attributes are sibling extractor functions composed at registration.
- **Effect diagnostics gate** (`pnpm check:effect`, part of `check:all`). `@effect/language-service` runs as a tsconfig plugin (in-editor) and in CI via `scripts/check-effect-diagnostics.mjs`, which fails on ANY finding. Keep it green: prefer `yield* someError` over `yield* Effect.fail(someError)` for yieldable (`Schema.TaggedErrorClass`) errors, declare handlers/endpoints with `Effect.fn`, and merge chained `Effect.provide(a), Effect.provide(b)` into one `Effect.provide(Layer.mergeAll(a, b))` (or `x.pipe(Layer.provideMerge(y))` when `y` satisfies `x`). Per-rule severities live in `tsconfig.base.json`'s plugin config — turn a rule `off` there **only** when it genuinely doesn't apply (e.g. `preferSchemaOverJson` is off: every JSON boundary here is a deliberate wire/test seam), never to dodge a real fix.
- **Effect v4 baseline.** Pinned to `effect@4.0.0-beta.94` (exact — `effect/unstable/*` may break on beta bumps). Domain result idiom is `effect/Result` (not `Either`); errors are `Schema.TaggedErrorClass`; services are `Context.Service<Self, Shape>()("Id")` with an explicit `Layer`. HTTP moved to `effect/unstable/httpapi` + `effect/unstable/http`. Persistence is `effect/unstable/sql` with the `@effect/sql-pg` driver, pinned to the same exact beta — bump them together. Two v4 gotchas contributors hit: `HttpApiClient` encodes a `Schema.Class` payload/params/query **strictly** — construct the contract class at the call site (`new SomeContract.CreatePayload({...})`), a plain object throws at runtime; and a service a module owns but an endpoint consumes (OIDC client, billing gateway) must be published as a bundled layer and provided **post-serve** at the composition root — `HttpRouter.provideRequest` type-checks but does not reach `HttpApiBuilder`'s routes at runtime.
- **Authentication via self-hosted Zitadel as a server-side BFF** (ADR-0016, ADR-0017). The SPA never holds access or id tokens; the server runs the OIDC dance and issues a `HttpOnly` session cookie. Application code consumes `CurrentUser` (`@org/contracts/Policy`); only `modules/auth/` and `platform/auth/` know about Zitadel. Roles live app-side in `users.role`; the seed script pre-seeds the admin's `users` + `auth_identities` rows so the first sign-in finds an existing identity.
- **Writing SQL.** `const sql = yield* Database.Database` gives the tagged-template client; a statement is an Effect returning rows. Decode explicitly — `Database.rows(RowSchema)`, `maybeRow` (→ `Row | null`, which is what `orFail` consumes), `row`, or `Database.exec` for a write — because effect/sql returns untyped rows and the `sql<Row>` generic is a type-level claim only. A row that does not match its schema is a defect, not a typed failure. `Database.mapSqlError` turns `SqlError` into the `DatabaseError`/`DatabaseUnavailable` vocabulary the ports speak, and the decode helpers apply it for you. Interpolated values are parameters; `sql(name)` is an identifier (dots become `"a"."b"`); an array binds as one parameter, so `= ANY(${ids}::uuid[])`. There is no `rowCount` — use `RETURNING` and count rows. `Effect.all` over two statements must stay **sequential**: inside a unit of work they share one transaction connection. `@effect/sql-pg` is importable only from `packages/database/src/` (dependency-cruiser `sql-driver-only-in-database-package`).
- **Per-module DB schemas** (ADR-0020). Each module owns a Postgres schema named after its folder — `user`, `organization`, `todos`, `wallet`, `auth`, `billing` — plus a shared `platform` schema for cross-cutting tables (the `role` module's data lives in `platform.roles`). Application SQL must address tables by their owning schema — `"user".users`, `todos.todos`, `wallet.wallets`, `auth.auth_identities`, `auth.sessions`, `platform.roles`. The `"user"` quotes are required (Postgres reserved word). Cross-schema FKs are allowed at DDL only (`wallet.wallets.user_id → user.users.id`, both `auth.*.user_id → user.users.id`); application SQL must never JOIN, SELECT, INSERT, UPDATE, or DELETE across schemas. Cross-module reads continue to flow through the synchronous event bus + interface/events ACL. Enforced by `local/no-cross-schema-sql-access` in `.oxlintrc.json` (scoped to `packages/server/src/modules/**`, excluding test files); a module whose schema is not its folder name is listed in the rule's own `SCHEMA_BY_MODULE` map. Adding a module: write a `Vxxx__create_schema_<name>.sql` migration and add `<name>` to `MODULE_SCHEMAS` in `packages/database/src/migrations.ts` — one place, shared by all three test harnesses.
